# Undertone iOS 0.4.0

## Scope

User deferred physical-device reliability checks, requested recording them and continuing product development. Canonical checklist: reports/IOS_DEVICE_CHECKS_LATER.md. User confirmed 0.3.0 works and scrolling no longer lags.

## Changes

- Queue sheet in the expanded player: current track and upcoming songs, tap to select, swipe removal, Edit reordering, clear upcoming, shuffle upcoming. Playing track and history are preserved while editing the tail.
- Local song context menu: play next or move/add to end. One queue entry per original identity; adding a previously queued song moves it. Queue is kept for the current app session only.
- Repeat off/all/one; repeat-one applies to natural completion, manual Next advances. Native and Vorbis completion share the same queue logic.
- Persistent library sort: title, artist, album, newest local added-at. Off-main sorting runs only when catalog/library/query/sort changes. Playlists preserve PC order. PC newest retains catalog order because catalog has no added-at timestamp.
- Album bulk download already existed in 0.3 and is retained. Original music files and Windows server are unchanged.

| Before | After |
|---|---|
| Player had an inaccessible internal queue | QueueView uses native List, editable upcoming rows and glass player controls |
| MusicLibraryView always used title order | Saved sort picker; filtering/sorting remain off-main |
