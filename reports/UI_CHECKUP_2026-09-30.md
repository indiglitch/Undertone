## Подтверждённые дефекты

### 1. Для второй строки плеера не хватает высоты — высокий приоритет

На живом экране таймлайн и подписи времени находятся почти на нижней границе панели, нижняя часть ползунка выглядит обрезанной. Кнопки занимают почти всю доступную высоту.

Причина: высота строки приложения для плеера по умолчанию 96 px, но сама панель имеет нижний margin 17 px и border. Остаётся около 77 px внутренней высоты. Последний CSS задаёт две строки `68px minmax(0, 1fr)`, поэтому для таймлайна остаётся около 9 px. Его range уже имеет `height: 4px` и вертикальные margins по 8 px, то есть требует как минимум 20 px. `overflow: hidden` скрывает выходящее содержимое. Увеличить плеер вручную можно, но начальная геометрия должна быть корректной без этого.

Места: [resizableLayoutModel.ts](F:/Spotify-Like/src/resizableLayoutModel.ts:6), [glassRedesign.css](F:/Spotify-Like/src/glassRedesign.css:541), [playerFreeLayout.css](F:/Spotify-Like/src/playerFreeLayout.css:4).

### 2. Начальные ширины панелей не соответствуют заданному дизайну — высокий приоритет

`finite()` преобразует `null` из отсутствующего localStorage ключа через `Number(null)`, получая 0. Вместо defaults размеры ограничиваются нижними пределами.

Запуск настоящей функции `loadLayout` с пустым storage при 1440×940 дал:

| Размер | Задано по умолчанию | Фактически получается |
|---|---:|---:|
| Sidebar | 260 px | 240 px |
| Правая панель | 335 px | 280 px |
| Строка плеера | 96 px | 96 px |

Это отдельный функциональный дефект загрузки настроек. Он усиливает тесноту правой панели и меняет композицию относительно ожидаемой. Сохранённые корректные значения восстанавливаются нормально.

Место: [resizableLayoutModel.ts](F:/Spotify-Like/src/resizableLayoutModel.ts:11).

### 3. Остатки старой темы видны в основных активных состояниях — средний приоритет

На экране активные лайки зелёные, а Play в нижнем плеере светло-зелёный, хотя остальные основные кнопки фиолетовые.

Причины различаются:

- В старом CSS осталось `.liked { color: #d5ed9b!important }`. Новая тема задаёт розовый цвет без `!important`, поэтому проигрывает каскаду.
- Новая тема оформляет Play через `.player-control-play .icon-button`, но реальная кнопка использует `.play-toggle`. Её фон и цвет наследуются из старого `styles.css`.

Это не намеренная целостная семантика цвета: старые селекторы продолжают действовать после редизайна.

Места: [styles.css](F:/Spotify-Like/src/styles.css:5), [styles.css](F:/Spotify-Like/src/styles.css:15), [glassRedesign.css](F:/Spotify-Like/src/glassRedesign.css:563), [player.tsx](F:/Spotify-Like/src/player.tsx:186).

### 4. Поисковое поле выглядит как узкое поле внутри другого поля — средний приоритет

В живом Search большая округлая строка содержит ещё одну отдельную тёмную рамку вокруг input. Внутренний input выглядит сплющенным по вертикали относительно кнопки и контейнера.

Старый `.search input` делает input прозрачным и без border. Поздний глобальный `input:not([type="range"])` с сопоставимой специфичностью возвращает ему border, background и radius. Получается наложение общего стиля обычных полей на специальный search control.

Место: [glassRedesign.css](F:/Spotify-Like/src/glassRedesign.css:287), базовый `.search input` в [styles.css](F:/Spotify-Like/src/styles.css:4).

## Риск адаптивной вёрстки по исходникам

Адаптация опирается преимущественно на ширину всего окна, хотя центральная область меняется при открытии и ресайзе обеих панелей. Поэтому при большой ширине окна центральная таблица может получить очень мало места, оставаясь в desktop-режиме. Например, в окне 1000 px при sidebar 240 px и правой панели 450 px центральная область имеет примерно 298 px ещё до margins/padding.

Есть и конкретный конфликт каскада: правило четырёх колонок `.track-grid` при `max-width: 760px` переопределяется поздним и более специфичным `.collection-track-area .track-grid`, которое задаёт шесть колонок. При этом правила скрытия колонок продолжают действовать. В native-окне минимум 1000 px, поэтому этот вариант относится прежде всего к browser preview или будущему уменьшению minWidth.

Рекомендуется переключать плотность таблицы и панели по доступной ширине контейнера, а не только viewport. В этой проверке уменьшенный размер native-окна не удалось надёжно установить через UI, поэтому узкие состояния не считаются визуально проверенными.

Места: [glassRedesign.css](F:/Spotify-Like/src/glassRedesign.css:804), [glassRedesign.css](F:/Spotify-Like/src/glassRedesign.css:1288), [resizableLayoutModel.ts](F:/Spotify-Like/src/resizableLayoutModel.ts:14).

## Общая причина

В [main.tsx](F:/Spotify-Like/src/main.tsx:4) последовательно подключаются несколько глобальных слоёв CSS; ниже сам компонент Player импортирует дополнительные стили. Одни и те же `.player`, `.track-grid`, `.sidebar`, `.details-panel`, `.search input` многократно переопределяются. В `glassRedesign.css` тоже есть несколько поздних поколений исправлений. Это делает фактический вид зависимым от специфичности и порядка правил, а не от одного понятного контракта компонента.

Несколько слоёв CSS сами по себе допустимы. Здесь проблема доказана конкретными проигравшими/неподходящими селекторами и несовместимыми размерами. Добавление ещё одного файла overrides будет увеличивать вероятность повторения.
