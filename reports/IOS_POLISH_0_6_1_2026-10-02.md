# Undertone iOS 0.6.1 — interaction, sync and lyrics

## Before / After

| Before | After |
| --- | --- |
| Background catalog polling every 30 seconds | 90-second fallback polling; foreground activation does not restart an existing polling task. Manual refresh and edit synchronization remain immediate. |
| Unchanged collection responses published new observable state and revisions | `PCCollections` equality suppresses unchanged collection/like/count publication and repeated state writes. |
| Every background refresh toggled the public busy flag | A private in-flight guard serializes requests; visible busy state is reserved for explicit refresh. |
| Unchanged catalogs were rewritten to disk | Decode/compare first; persist and regroup only changed tracks. |
| Album menus sorted the complete catalog while being constructed | Actions resolve on selection; album actions filter local tracks first and use cached PC album grouping. Album tile metadata reads its own album directly. |
| Home playlist label determined its intrinsic width | Flexible grid cells and stretched labels provide equal widths; titles wrap within their cell. |
| ADD and SYNC shared a toolbar glass group | Separate toolbar groups and extra spacing, using Apple's shared-background API. |
| Plain buttons had little press feedback | Reusable 0.96 scale/opacity feedback and selection haptic; Reduce Motion disables scaling. Native system menu highlighting remains native. |
| Scroll boundaries clipped content abruptly | Fixed 12/18-point alpha edge fades; track rows use subtle native scroll-transition opacity/scale. No blur or per-frame geometry state. Forms, queues, lyrics, player and PC screens share the edge treatment. |
| Search used a large navigation title and large top region | Compact inline SEARCH title. |
| Shuffle was a one-shot randomization with no enabled state | Reversible toggle with accented background and ON/OFF accessibility value; disabling restores retained original order while preserving new queue additions and current track. |
| Shuffle state was absent from saved sessions and collection playback | Shuffle state/original order persist with backward-compatible optional snapshot fields. Collection SHUFFLE starts the same tracked mode. Repeat also has an accented enabled background/value. |
| Queue EDIT and SELECT occupied one HStack/group | Separate leading/trailing toolbar items and independent edit/selection modes. |
| Action captions were mixed Russian/English | App-controlled static actions, tabs, filters and sorting options use uppercase English. Track/artist/album/playlist metadata are preserved; OS-owned dialogs retain OS localization. |
| Lyrics requested once for only one PC identity | Retry on reconnection/catalog change; resolve all PC identities; ignore empty documents; REFRESH LYRICS explicitly retries. |
| Lyrics did not accompany downloaded originals | Download-completion callback caches the matching song's lyrics without scanning every song. Valid local/imported text remains cached. |
| Running PC companion 0.3 returned 404 for lyrics | Running process replaced with existing verified PhoneSync 0.5 build. Pinned authenticated request returned 200 and 1,973 text characters. Encrypted pairing identity remained byte-identical. |
| Preview had inconsistent action captions and shuffle indicators | Preview mirrors compact English actions, equal columns, separate controls, press feedback/fades and tracked shuffle. It remains a demo, not an iOS emulator. |

Apple toolbar API: https://developer.apple.com/documentation/swiftui/toolbarcontent/sharedbackgroundvisibility(_:)

## Boundaries

The repeated observable updates and menu/catalog work were confirmed in source. They are plausible contributors to the user's lag; no physical-device frame-time profile was captured, and an improvement on the user's iPhone must be confirmed after installing 0.6.1. Fixed fades and native transitions avoid introducing continuous geometry publishing or blur.

Physical-device signing, Wi-Fi/background transfer and update-preservation checks remain deferred in IOS_DEVICE_CHECKS_LATER.md. Only lyrics already stored on the PC can be transferred; fetching absent lyrics from providers is a separate desktop operation. Updating the PC does not imply the user's iPhone has already displayed the text.
