# Undertone Mobile UX — этапы 1–10

Обновлено: 2026-10-19. Этапы 1–9 реализованы в исходниках; этап 10 завершил доступную локальную QA и точечные исправления. По предоставленному 19.10.2026 артефакту нативная компиляция и 76 unit-тестов подтверждены; общий CI failed (29 UI-сбоев и timeout второго размера). Исправления после анализа ещё не запускались в CI; полная готовность не заявляется.

## Инварианты

Нативная CI-приёмка подготовлена отдельным ручным workflow **iOS Simulator Checks**: [запуск и артефакты](ios-ci-testing.md). Он компилирует текущую ветку, запускает unit/UI на одном размере и smoke/screenshots на втором. На момент добавления workflow GitHub Actions run не выполнялся; открытые пункты нативной приёмки ниже не отмечены пройденными.

- Сохраняем чёрно-фиолетовую палитру (`canvas`, `undertone`), скругления, полупрозрачное системное стекло и fallback Reduce Transparency. Собственная идентичность Undertone; без копирования Spotify/Apple Music.
- SwiftUI/iOS 26+, существующие NavigationStack, состояние вкладок, sheet-презентации, жесты, PressFeedbackStyle и Reduce Motion остаются основой. Не заменяем архитектуру или стек.
- Desktop, оригинальные аудиофайлы, локальное воспроизведение, очередь, сохранения и синхронизацию не меняем. Незакоммиченные изменения сохраняем; без коммитов и новых зависимостей.
- Один владелец нижнего пространства: TabView + мини-плеер. Страницы и вложенные списки не добавляют высоту Tab Bar, плеера или home indicator в padding. `ignoresSafeArea` разрешён фону, не контенту.
- Последняя строка должна полностью прокручиваться выше панелей, включая её меню. Высоту резервирует системный accessory/safe-area inset; никаких фиксированных «компенсаций» на отдельных экранах.
- Зоны мини-плеера не пересекаются и имеют минимум 44×44 pt. Длинные названия сокращаются; в inline/Accessibility Dynamic Type остаются открытие плеера и play/pause, остальные действия доступны в Now Playing и контекстном меню.
- При клавиатуре мини-плеер и Tab Bar скрываются, высоту клавиатуры учитывает SwiftUI. Закрытие клавиатуры возвращает панели. Полноэкранный плеер и модальные окна используют собственные системные safe areas и не получают ещё один нижний dock.

## Этап 3 — Search

Мобильный поиск выделен из LibraryHubView в MobileSearchView. Остальные объявления LibraryHubView сохранены; RootView, Home, нижние панели, MusicLibraryView, TrackCatalog/общие строки, коллекции, воспроизведение, синхронизация и хранение истории не изменены.

| Область | Реализация |
| --- | --- |
| Состояния | Пустой/пробельный запрос — отдельная Search History или приглашение ввода, без полного списка музыки. Непустой запрос — индикатор на время 180 ms debounce/локального вычисления, затем Results с количеством либо «Ничего не найдено» для любого фильтра. История и результаты одновременно не показываются. |
| Ошибки | Реальные ошибки библиотеки, сохранения истории и действий с результатами остаются в существующем AppErrorToast; запрос/фильтр/доступные результаты сохраняются. Локальное сопоставление не бросает ошибок, отмена поиска не считается ошибкой. Офлайн-режим сам по себе не является ошибкой поиска; новый сетевой retry или вымышленный error state не добавлены. |
| Модель/источники | MobileSearchResults использует прежний TrackCatalog.merged, сортировку librarySort и localizedCaseInsensitiveContains: Songs — title/artist/album, Albums — объединённые ключи альбомов, Artists — уникальные исполнители, Playlists — имена существующих плейлистов. Непустой текст не нормализуется дополнительно; без транслитерации, fuzzy matching и новых источников. |
| История | Переиспользованы PersonalLibrary.rememberSearch/update и прежний лимит 20. Отдельные действия: clear поля, удаление одной записи, clear history. Выбор записи выполняет её повторно, сохраняет активный фильтр и закрывает клавиатуру. Очистка поля сохраняет историю и оставляет фокус для следующего ввода. |
| Фильтры/нажатия | Songs / Albums / Artists / Playlists сохранены. Активность выражена заливкой, фиолетовым контуром, начертанием и accessibility selected. Новые кнопки и поле имеют зоны от 44 pt; фильтры при Accessibility Dynamic Type переходят в два столбца, история переносится на две строки. Автокоррекция/автокапитализация поля выключены. |
| Фокус/позиция | Единственный Done и submit сохраняют запрос в историю и убирают клавиатуру; выбор фильтра тоже убирает её. List сохраняет interactive keyboard dismissal. Новый запрос/фильтр прокручивает к началу; Back и переключение вкладок не очищают query/filter и не запускают принудительный scroll-to-top. Foundation продолжает управлять нижним пространством. |
| Асинхронность/действия | Снимок результата привязан к запросу/фильтру/нужным ревизиям; task cancellation и проверка актуальности перед публикацией исключают подмену новым запросом старого результата. Изменения истории, фокуса или playback не входят в ключ поиска. Результаты используют прежние UnifiedTrackRow, SharedAlbumLink, SharedPlaylistLink и MusicLibraryView для коллекций; Songs сохраняет прежнюю очередь, Undo Delete и ручной pull-to-refresh. Набор текста сам не вызывает сеть. |
